# F-Droid

KeyHack is set up to be built by F-Droid. The store listing (title,
descriptions, icon, screenshots and per-version changelogs, in English and
Brazilian Portuguese) lives in [`fastlane/metadata/android`](../../fastlane/metadata/android),
where F-Droid reads it from the source.

[`com.reinanbr.keyhack.yml`](com.reinanbr.keyhack.yml) is the build recipe
for the [fdroiddata](https://gitlab.com/fdroid/fdroiddata) repository. It
passes `fdroid lint` and `fdroid rewritemeta`, and `fdroid scanner` finds no
problems in the source.

- **Flavor:** F-Droid builds the `online` flavor, with GIF search. Giphy is a
  non-free network service, so the recipe declares the `NonFreeNet`
  anti-feature. The `offline` APK stays on the GitHub releases page.
- **JDK:** the Gradle build needs JDK 21, which the recipe installs.
- **Data files:** dictionaries and next-word models are plain text,
  generated by `tools/gen_dict.py` and `tools/gen_ngrams.py`. F-Droid's
  scanner refuses archives such as `.gz` in the source.
- **Signing:** F-Droid signs the APK with its own key. It cannot update an
  install of a GitHub release (different certificate), and the reverse is
  true too.

## Submitting

1. Tag the release (`vX.Y.Z`) and push it.
2. Fork fdroiddata on GitLab, copy the recipe to `metadata/`, and update
   `versionName`, `versionCode`, `commit` and `CurrentVersion*` if needed.
3. Run `fdroid lint com.reinanbr.keyhack` and
   `fdroid build -v -l com.reinanbr.keyhack`, then open a merge request.

After that, `UpdateCheckMode: Tags` picks up each new tag on its own.

## Later: reproducible builds

F-Droid can publish the developer-signed APK instead of signing its own,
when its build matches the release byte for byte. That needs `Binaries:`
(the release APK URL) and `AllowedAPKSigningKeys:` (the certificate SHA-256
in the main README) in the recipe, and a check that the build really is
reproducible. Baseline profiles are a known source of differences.
